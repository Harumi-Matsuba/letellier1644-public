# 方法・数字・AI の使用・限界

## 画像
- BnF Baluze 103（Gallica ark:/12148/btv1b9001389d）。f. 50r＝111コマ、f. 50v＝112コマ。openapi.bnf.fr の IIIF から原寸（4864×6996）で取得した。画像はこのリポジトリに含めていない。
- 鍵の確かめに使った兄弟書簡：f. 230r（486コマ）と当時の解読文 f. 232r（490コマ）。語の符号の確かめに f. 171r（366）、f. 189r（402）、f. 200r（424）、f. 230v（487）を見た。

## 鍵（`data/key.tsv`）
1. 土台は友清理士氏の表（Cryptiana louisxiv0.htm「Le Tellier-Marca Cipher (1644)」の画像）を、記号名に置き換えたもの。
2. f. 230r の暗号文の18行を、当時の解読文 f. 232r と1記号ずつ対応させ（`data/f230r_pairs.txt`、`data/f232r_decipherment.txt`）、表の値を確かめ、表にない記号の値を足した（R＝c、ʒc・ʒx＝r、ꝺ＝r、ℒ＝M、Ꝺ＝h、k＝u）。確かでない組には ? を付けてある。
3. 語の符号：=9 pour、=11 que、=12 qui、=26 vous、=32 Barcelone、81 faire、39 Catalogne、=y Monsieur le Mareschal、=3 de La Motte、=11 =o la Reyne、=l =m du Roi。=3 は f. 230r と f. 200r、=11 =o は f. 189r の3か所と当時の解読文の照合で確かめた。
4. source の列：T＝友清氏の表にある、S＝f. 230r／f. 232r の照合で確かめた、X＝別の AI との照合で分かれた記号、C＝f. 50 の文脈だけからの推定。
- 当初、6 を t と l、y を n と g の両方に使う記号と考えていたが、別の AI との照合（下）で、l に当たるのは σ形の別の記号、n に当たるのは横線のある y だと分かった。友清氏の表の列分けのとおりだった。f. 230r の対応表（`data/f230r_pairs.txt`）は、この区別をする前に作ったもので、見直していない。

## 書き起こし（`data/transcription_f50.txt`）
- Claude が原寸の行画像を見て、記号名で1回書き起こした（`data/transcription_f50_before_xcheck.txt`）。
- 2回目：別の AI（OpenAI Codex CLI、ChatGPT アプリ同梱 codex-cli 0.163.0-alpha.10.2、既定のモデル）に、画像と記号名の一覧（形の説明だけ。値・1回目の書き起こし・鍵・解読文は含めない）だけを渡し、5回独立に書き起こさせた。1〜3回目は1行1枚（`second/PROMPT.md`）、4〜5回目は1行を左右2枚に切った画像（`second/PROMPT_halves.md`）。5回とも、実行記録にコマンドの実行やファイルの読み込みはなかった。
- 1回目と Codex 1〜3回目の一致：633記号のうち 565・554・559、3回とも一致 546。食い違いを原寸で見直し、σ形10、横線のある y 9、24 の2か所などを直した（`second/RESULT.md`）。
- 5回の投票：最終の626記号のうち、5回とも同じ 581、多数が一致 613、多数が別の名前 11、多数なし 2。多数が違った15か所（再改訂前）を画像で見直し、4か所を直した（`second/VOTE.md`）。
- **AI どうしの比較は、人による確認の代わりにはならない。人による書き起こしの確認はしていない。**

## 対照（`src/control.py`、`controls/run.sh` → `controls/results.txt`）
鍵の値をかき混ぜた鍵 1000 通りと、文字3連のフランス語らしさ（wordfreq の仏語上位5万語から作る）で比べた。

| 書き起こし | 鍵 | 本物の鍵 | かき混ぜの最大 | 本物以上 |
|---|---|---|---|---|
| 最終（32行） | 全記号（70） | −3.458 | −4.942 | 0/1000 |
| 最終（32行） | 友清氏の表の記号だけ（57） | −3.370 | −4.867 | 0/1000 |
| 最終（32行） | f. 50 の文脈から推定した値（source が C だけ）を外した鍵（65） | −3.421 | −4.726 | 0/1000 |
| 最後の5分の1（f. 50v 7〜12行） | 全記号 | −3.182 | −4.510 | 0/1000 |
| 最後の5分の1 | 推定した値を外した鍵 | −3.182 | −4.545 | 0/1000 |
| Codex 1〜5回目 | 全記号 | −3.682／−3.670／−3.619／−3.647／−3.627 | −4.934／−4.880／−4.873／−4.890／−4.962 | 各 0/1000 |

- 「推定した値を外した鍵」は `controls/key_without_target.tsv`（ae、9f、l、24、23hat を外した）。f. 50 そのものから値を決めた記号を使わなくても読める、という確かめ。
- 最終の書き起こしの値（−3.458）は、照合前（−3.421）より少し下がった。似た記号を文脈で選んでいた箇所を、画像どおりに直したため。

## 較正（`calib/`）
答えのある f. 171r の12〜24行目を同じ鍵で読み、読みを固定してから（SHA-256 を `calib/hashes_before_answer.txt` に記録）、当時の解読文 f. 172r と比べた。

| 測ったもの | 結果 |
|---|---|
| 記号ごとの精度（主な値と別の値を許す、`src/score_signs.py`） | 0.924（256/277） |
| 記号ごとの精度（主な値だけ） | 0.874（242/277） |
| 読みの文字の一致（`src/calib.py`） | 93.6%（337/360） |
| 鍵を機械的に当てただけの文字の一致 | 84.2%（303/360） |

誤りの例と限界は `calib/RESULT.md`。13行だけの較正で、盲検も完全ではない（同ページの冒頭に当たる f. 172r の7行を、先に NoAutopilot の書き起こしで読んでいたため、1〜11行目は使わなかった）。較正で分かった「横線のない 12 19＝qu'il」「9 の上に小さな g＝Sr」は、答えを見た後に分かったので鍵には入れていない。

## 先行研究との関係
- 友清理士氏：鍵の表と、この書簡が「undeciphered」であること。
- NoAutopilot/cipher-lab（`ciphers/baluze103-letellier-marca-1644/`、最後のコミット f3dcded、2026-10-13、Status: partial／Verdict: parked）：f. 50 を友清氏の表で部分的に読んだ下書き（630記号中451に値）がある。こちらで使ったのは、Gallica のコマ番号の対応、openapi.bnf.fr から画像が取れること、f. 200r で 6 が l にも当たるという記録、f. 190r と f. 205r の当時の解読文の書き起こし（f. 189r と f. 200r の照合に使った）。f. 50 の書き起こしと読み、f. 230 の照合、較正は、彼らのものを使わずに作った。

## AI の使用
書き起こし・鍵の補い・解読・スクリプト・文書は、Anthropic の Claude（Claude Code、Claude Opus 5.5）が行った。書き起こしの照合に OpenAI の Codex を使った。対象の選定、作業の指示、公開の判断は人が行った。
